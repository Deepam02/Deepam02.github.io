Multi-Agent Platform AWS EKS Production

SWARM — Agent Orchestration for Telco

ap-southeast-1 · Kubernetes · Google ADK · LiteLLM

Most "multi-agent" projects are two LLM calls in a trenchcoat. SWARM is different — each agent runs in its own Kubernetes sandbox pod, spawned on demand, wired to real enterprise systems. I built the whole thing: infrastructure, orchestration, integrations, and the agent logic. Shipped three templates that are actually running.

  • Ticket-email routing: Jira webhook → pod spawn → classify → escalate via AgentMail
  • L1/L2 network triage with alarm correlator and change management lookup
  • Reply handling via Svix signature verification + atomic SQL state transitions
  • Thread-ID-based routing so agents maintain conversation context across turns
  • Terraform-managed EKS cluster with per-agent pod lifecycle
  • LiteLLM as a unified LLM gateway across providers

02
AI Product 100k+ Customers Full-Stack

AutoCLM — WhatsApp at Scale, for Telcos

Singtel · WhatsApp API · LangGraph · React

Telcos send the same SMS to 100,000 people on the same day and call it "personalisation." AutoCLM replaces that with continuous, 1:1 AI conversations — each customer on their own journey arc, managed by an AI planner, executed by a conversational agent called Stella. I designed the architecture and shipped the full-stack demo.

  • Blueprint layer: human-defined strategy, tone guardrails, offer limits
  • Journey Agent: continuously plans engagement arc per customer across 100k+ base
  • Stella: conversational agent executing WhatsApp messages 1:1 at scale
  • WhatsApp-style chat UI with 5 realistic customer personas and backstories
  • Team dashboard with Morning Briefing, Cohort Live View, Simulation Sandbox
  • Verified Singtel postpaid plan data — six 24-month contract tiers

03
AI Infrastructure Hybrid Search Architecture

Information Repository — Production RAG

Qdrant · BM25 / RRF · Cohere Rerank · FastAPI

The first version was scrapped. I rebuilt it from scratch because "close enough" isn't acceptable when an AI is quoting plan prices and device specs to real customers. The v2 architecture uses four content zones, hybrid retrieval with RRF fusion, Cohere reranking, and LLM-generated chunk labels — so what the model retrieves is actually what it needs.

  • Zone A/B/C/D: images, URLs, structured knowledge, unstructured FAQs
  • Dense + BM25 sparse retrieval fused with Reciprocal Rank Fusion
  • Cohere rerank-v3.5 via OpenRouter as final relevance pass
  • LLM-generated document titles and per-chunk topic labels at embedding time
  • Approval loop — all ingested content reviewed before going live
  • Soft deletes only; full audit trail; native Qdrant payload filtering
